Сравнение конкурентов Claude Code GUI и план работ

claude-web · opcode · claudecodeui · jetbrains-cc-gui

Ключевой вывод: из трёх конкурентов только у jetbrains-cc-gui есть настоящее новаторство в подходе — он сделал «каждое сообщение автоматически несёт код, который пользователь сейчас смотрит» поведением по умолчанию, и рост качества ответов виден невооружённым глазом. opcode и claudecodeui по сути проекты типа «список функций» (браузер сессий, панель использования, редактор конфигурации), их можно скопировать, но копирование не меняет класс продукта.

Отсюда принцип планирования: автоматическая инъекция контекста > нагромождение панелей конфигурации. Уже отрезаны 6 низкорентабельных требований: редактор Hooks, Command Palette, визуализация временной шкалы, несколько провайдеров, система плагинов, голосовой ввод.

Вывод: из четырёх проектов неагентный режим чата есть только у нас. Ни один проект не сделал чистого диалога через прямой API Anthropic.
Суждение: в ближайшее время не срочно. Существующего чата CLI достаточно, «чистый диалог» не является ключевым сценарием Claude Code GUI. Оставляем до v3.0 как точку дифференциации.

План работ

7 пунктов, отсортированы по «степени изменения класса продукта», а не по «объёму работ». Количество недель — оценка для одного разработчика.

v2.3 Автоматизация контекста — пользователю больше не нужно вручную вставлять код
2 недели
1. Система упоминаний @ (файлы / терминал / запущенные процессы) jetbrainsclaudecodeui около 3 дней
При вводе @ всплывает список кандидатов, можно ссылаться на файлы проекта, последний вывод текущего терминала, запущенные процессы. jetbrains сделал терминал и конфигурации Run тоже псевдо-файлами, на которые можно ссылаться через @, — этой идеи нет ни у одного из двух веб-конкурентов: «прикрепить к AI то, что происходит прямо сейчас».
Реализация
  • Фронтенд: в поле ввода @ открывает popup + нечёткая фильтрация (переиспользовать существующий интерфейс code-tree)
  • Бэкенд: добавить GET /api/sessions/{id}/mentionable, возвращающий дерево файлов + активные терминалы + запущенные процессы
  • После выбора вставляется маркер @path/to/file, перед отправкой бэкенд разворачивает его в реальное содержимое
2. Автоинъекция текущего файла (с переключателем) jetbrains около 2 дней
Файл, открытый в инспекторе кода, и выделенный диапазон строк по умолчанию прикрепляются к каждому сообщению как контекст. Именно в этом коренная причина высокого качества ответов плагина jetbrains, а не в различии моделей. Делаем переключаемым, чтобы длинные файлы не тратили токены впустую.
Реализация
  • Фронтенд запоминает текущий файл инспектора + диапазон выделенных строк и отправляет их вместе с ChatRequest
  • Бэкенд формирует блок <ide_context> и добавляет его к system prompt (переиспользуя путь инъекции memories)
  • Рядом с полем ввода — переключатель + оценка токенов; сверх порога инжектируется только выделенный фрагмент
3. Воспроизведение при переподключении SSE после обрыва claudecodeui около 2 дней
Удалённый доступ по OTP с мобильного — наша уникальная возможность, но при обрыве сети SSE теряет события, и длинная задача пропадает впустую. Протокол SSE нативно поддерживает переподключение через Last-Event-ID, переходить на WebSocket не нужно. Это долг по надёжности, а не новая функция.
Реализация
  • Каждому событию SSE добавляется автоинкрементное поле id:
  • Сервер поддерживает на каждую сессию кольцевой буфер deque(maxlen=5000) с истечением через 5 минут
  • При переподключении читается заголовок запроса Last-Event-ID и досылается недостающий диапазон
v2.4 Переиспользование рабочих процессов и опыт утверждения
3 недели
4. Библиотека пользовательских Agent + шаблоны сессий opcodejetbrains около 1 недели
Определения Agent в opcode (имя/значок/системный промпт/модель/разрешения/hooks с экспортом .json для обмена) вместе с шаблонами сессий jetbrains (модель/режим разрешений/cwd, сохранённые как именованный снимок) дают пользовательские переиспользуемые рабочие процессы. CLI этого не может, и это основа для Agent-маркетплейса командной версии.
Реализация
  • Таблица agent_templates: name / icon / system_prompt / model / permission_mode / default_task / cwd
  • CRUD + клонирование + экспорт-импорт .json
  • При создании сессии «создать из шаблона» заполняет в один клик; system_prompt идёт через существующий канал append-system-prompt
5. Diff можно отредактировать, затем принять jetbrains около 4 дней
Сейчас при утверждении разрешений можно только принять всё или отклонить. jetbrains позволяет редактировать diff справа: пользователь слегка правит изменения AI и затем применяет их — это устраняет тупик «в целом верно, но в одном месте не так, остаётся только отклонить и начать заново». Из трёх конкурентов это сделал только он.
Реализация
  • Интерфейс предпросмотра разрешений уже есть (preview-change); правую колонку фронтенда заменяем на редактируемый редактор
  • Добавить «принять изменённую версию»: отредактированное содержимое возвращается как результат утверждения и перекрывает исходные входные параметры tool
  • Нужна поддержка approve с изменённым содержимым на уровне bridge
6. AI-генерация Commit Message jetbrains около 2 дней
Читает staged diff, разовый вызов (maxTurns=1, сессия не создаётся, история не сохраняется), токены потоково пишутся в поле ввода. Объём работ небольшой, но демонстрационный эффект хороший и нужен каждый день. Из трёх конкурентов хоть какая-то интеграция записи в VCS есть только у jetbrains.
Реализация
  • Кнопка в панели Git → POST /api/git/commit-message
  • Бэкенд читает staged diff и выполняет разовый query через bridge (в историю session не пишется)
  • Потоковая передача через SSE, фронтенд по токенам пишет в поле ввода message
v2.5 Визуализация конфигурации и прозрачность стоимости
1.5 недели
7. Управление CLAUDE.md и Slash Commands opcodeclaudecodeui около 4 дней
CLAUDE.md — файл, который пользователи Claude Code меняют чаще всего, а сейчас для этого приходится прыгать в редактор. Достаточно сделать панель: рекурсивное сканирование всех CLAUDE.md внутри проекта + сканирование .claude/commands/*.md (с разбором YAML frontmatter).
Примечание: визуальный редактор Hooks из opcode уже отрезан — фактическая частота изменений намного ниже, чем у CLAUDE.md, и вложения не окупаются.
Реализация
  • Рекурсивный поиск CLAUDE.md (две области действия user / project), markdown-редактор + сохранение
  • Сканирование ~/.claude/commands/ и .claude/commands/ с разбором description / allowed-tools из frontmatter
8. Глобальный дашборд использования / стоимости opcode около 3 дней
У нас уже есть запись usage за один раунд, не хватает агрегированного вида по всем сессиям. Подход opcode можно просто повторить: пройти по ~/.claude/projects/**/*.jsonl, дедуплицировать по message.id + requestId, агрегировать по модели/дате/проекту, при отсутствии costUSD подставлять значение из таблицы цен. Предшественник контроля бюджета командной версии.
Реализация
  • Переиспользовать существующую таблицу session_usage как основной источник данных, сканированием JSONL дополнить нативные сессии CLI
  • Ключ дедупликации message.id + requestId; таблица цен как подстановка при отсутствии costUSD
  • Панель: обзор + по модели / по дате / по проекту, с фильтром по диапазону дат

Наши существующие преимущества (moat)

Возможности, которых нет ни у одного из трёх конкурентов; при разработке новых функций следите, чтобы их не ослабить.

Автоматические раунды Agent Loop
Лимит 20 раундов + бюджет токенов + проверка тестовыми командами. Единственный GUI, поддерживающий непрерывное выполнение без присмотра.
Удалённый доступ по OTP с мобильных
Код доступа / TOTP + белый список путей. Остальные три — все только локально.
Расширение для браузера Chrome
Форма боковой панели, двойной режим только чтение / полный. Единственное решение, встраиваемое в рабочий процесс браузера.
Memories + Pinned Docs
Межсессионная постоянная память + инъекция закреплённых документов уровня сессии.
Оптимизатор промптов
Сбор образцов + управление правилами + переписывание. Систематизированный инструмент prompt engineering.
Онлайн-выполнение блоков кода
Кнопка Run сразу запускает Python/JS, не нужно вручную копировать в терминал.
Серверная очередь сообщений
Постоянная очередь в БД + последовательная диспетчеризация. У claudecodeui только клиентский localStorage.
Автоматизированная проверка в браузере
Проверка фронтенд-изменений на основе Recipe с сохранением доказательств.

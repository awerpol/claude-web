Claude Code Web 2.0 — это локальный веб-интерфейс для [Claude Code](https://docs.claude.com/claude-code). Рабочий режим использует нативные постоянные сессии Claude Agent SDK, а обычный чат сохраняет путь через CLI `claude`; у обоих runtime строгая принадлежность сессий, и при сбое они не переключаются неявно друг на друга. Фронтенд через SSE показывает ответы, выполнение инструментов, состояние размышления и изменения файлов.

```bash
pip install --upgrade claude-web-ui
claude-web --open
```

> 🔒 **О приватности**: этот инструмент — лишь локальная графическая оболочка над CLI `claude`, он не загружает никакие данные в сторонние сервисы. Все диалоги, изображения и история сессий хранятся на этой машине в `history/`, `uploads/` и `claude-web.db`. Аутентификация использует состояние входа вашего локального `claude` (`~/.claude/`), инструмент не касается никаких API Key.

> Текущая документация соответствует `2.1.2`. Историю изменений см. в [CHANGELOG.md](CHANGELOG.md), настройку Authenticator — в [TOTP_SETUP.md](TOTP_SETUP.md).

## Ключевые изменения 2.0

- **Разделение чата и рабочего режима**: обычный чат скрывает контекст разработки проекта; рабочий режим показывает проект, ветку, разрешения, модель, силу рассуждений и состояние локального выполнения.
- **Новая боковая панель**: чат, поиск, записи, импорт CLI и рабочая область кода объединены в навигацию списком.
- **Вывод кода в стиле Codex**: скрыты элементы обратной связи обычного чата, централизованно показываются план, прогресс инструментов, изменения файлов и результаты кода.
- **Компактное меню моделей**: главное меню показывает только модель и силу рассуждений, конкретные параметры — в левом и правом подменю; на узких экранах сторона переключается автоматически.
- **Сессии кода группируются по проектам**: сессии, привязанные к проекту, появляются только в рабочей области кода и могут быть удалены из меню сессии.
- **Работа с разрешениями в рабочем режиме**: рабочая область кода по умолчанию использует автоматический режим и напрямую пропускает такие инструменты Claude Code, как Bash, чтение и запись файлов, поиск, Task; в окружении root / sudo автоматически переключается на совместимый запуск с белым списком всех инструментов.
- **Нативные сессии Agent SDK**: рабочий режим управляется постоянным Node bridge, который держит Claude Query; каждый раунд отправляет только сообщения этого раунда и использует нативный Session ID, инструменты, Hooks, Skills, MCP, автоматический compact и управление прерыванием, а веб-слой больше не склеивает всю историю заново.
- **Размышления включены по умолчанию**: рабочая область кода по умолчанию включает процесс размышления и отправляет среднюю силу рассуждений; в настройках её можно отключить или изменить.
- **Лёгкий контекст в рабочем режиме**: прямой вызов SDK `getContextUsage()` для получения `totalTokens / maxTokens`, кольцо показывает оставшуюся долю; окно определяется локальной конфигурацией модели и может быть 200k или 1M. При достижении верхней отметки 80% через специальный управляющий интерфейс запускается нативный `/compact` Claude Code, Session ID при этом сохраняется.
- **Сводка изменений файлов**: после ответа, изменившего файлы, показывается список файлов, который можно открыть для просмотра диффа.
- **Прогресс выполнения инструментов**: панель инструментов показывает количество выполнений, типы, степень завершённости и состояние работы.
- **Переработка мобильной версии**: поисковый слой, ящик боковой панели, нижнее поле ввода, модальные окна и безопасные зоны оптимизированы единообразно.
- **Центр настроек**: уведомления, мобильный доступ, расширение для браузера, статистика расходов, память и прочие настройки собраны в одном месте.

## Основные возможности

### Диалог и ввод

- Многораундовый диалог, остановка генерации, ветвление сессии, продолжение после редактирования истории.
- Вставка / перетаскивание / загрузка изображений, извлечение текста из PDF, DOCX, PPTX, XLSX, CSV, TXT, MD и других документов.
- Извлечение текста по URL, поиск в сети через WebSearch / WebFetch.
- Ссылки на файлы через `@` и Slash-команды: `/new`, `/clear`, `/fork`, `/compact`, `/init`, `/review`, `/test` и др.
- Автосохранение черновиков, оценка токенов, подсказки о длинном контексте и ручное сжатие через `/compact`.
- Переключение моделей Opus / Sonnet / Haiku и сила рассуждений низкая / средняя / высокая / очень высокая.

### Рабочая область кода

- Проект, ветка Git и состояние рабочего каталога.
- Project Map поддерживает структуру проекта, доказательства из исходников, фильтрацию связей, историю ревизий и анализ влияния вверх и вниз по потоку; узлы можно прикреплять как Context Pack с ограничением по версии к Plan, задаче или черновику теста.
- Git Worktrees позволяют из текущей сессии кода создавать изолированные каталоги, ветки и производные сессии; проверка изменений поддерживает Stage / Unstage на уровне файлов, при этом индекс Git и «сохранить / отменить изменения AI» остаются независимыми друг от друга.
- Context Ledger показывает источники и жизненный цикл контекста, такие как SDK usage, Project Map Pack и нативный compact; Review может регистрировать рецепты приёмки в браузере, Run и доказательства, не выдавая себя за выполнение внешних браузерных или серверных команд.
- Четыре режима работы: обычный, планирование, агент, автоматический; в окружении root / sudo автоматически переключается на `acceptEdits + белый список инструментов` для совместимости с ограничениями безопасности Claude CLI.
- Визуализация инструментов Bash / Read / Write / Edit / Grep / Glob и др.
- Полосы прогресса инструментов, сворачивание деталей инструментов, показ процесса размышления по умолчанию, сводка изменений файлов и просмотр диффа.
- Контрольная точка Git и транзакционный откат (только для репозиториев Git): сохраняются существующие staged / unstaged / untracked файлы, откат запрещён для выполняющихся задач, при сбое автоматически восстанавливается состояние на момент нажатия отката.
- Нативное ветвление сессий и откат файлов: повтор истории, продолжение после редактирования и ветвление вызывают нативные интерфейсы сессии SDK; откат контрольной точки файлов Claude SDK и откат контрольной точки Git сосуществуют.
- Нативное управление runtime: модель и режим разрешений можно переключать внутри сессии через SDK; при переключении на `bypassPermissions` и обратно безопасно пересоздаётся простаивающий Query с сохранением исходного Session ID.
- Продолжение после обрыва связи и восстановление после прерывания: обновление страницы браузера или разрыв SSE не останавливают Claude; бэкенд продолжает обрабатывать и сохранять события, а при повторном открытии сессии восстанавливаются состояние выполнения и карточки инструментов, ожидающих подтверждения.
- Быстрые входы для проверки кода, объяснения ошибок, генерации патчей и добавления тестов.
- Agent Loop: непрерывное выполнение, тестирование и исправление по цели, числу раундов, бюджету добавочных токенов и тестовым командам; в бюджет входят только новые промпты и вывод модели, уже существующий контекст сессии / cache не пересчитывается.

### Сессии и локальные данные

- Закрепление, архивирование, метки, поиск, экспорт и AI-именование сессий.
- Раздельный показ обычного чата и сессий, привязанных к проектам.
- Импорт сессий Claude Code CLI из `~/.claude/projects/`, по умолчанию загружаются последние 10, остальное — по мере прокрутки.
- Метаданные сессий хранятся в `claude-web.db`, события — в `history/*.jsonl`, вложения — в `uploads/`.
- Данные по умолчанию остаются на этой машине, используется состояние входа локального Claude Code, Anthropic API Key не читается и не сохраняется.

### Коннекторы (MCP Server)

- **Каталог коннекторов в один клик**: встроенные часто используемые MCP-коннекторы (GitHub, Notion, Sentry, Postgres, Tushare и др.), сгруппированные по категориям финансы / офис / разработка / сеть / исследования, выбор сразу заполняет форму добавления.
- **Локальная / удалённая передача**: поддерживаются stdio (локальная команда) и http / sse (удалённый MCP Server), у удалённого коннектора можно указать URL и заголовки запроса, есть проверка работоспособности соединения.
- **Шифрованное хранение ключей на этой машине**: при включении «шифровать ключи при сохранении» API Key / Bearer и другие чувствительные заголовки и переменные окружения шифруются главным ключом этой машины (предпочтительно OS keychain, иначе `~/.claude/.cw_connector_key`, права `0600`) и сохраняются в `claude-web.db`, а в `.mcp.json` остаётся только ссылка `cwsecret://`; расшифровка и подстановка происходят только при запуске сессии, в открытом виде данные не записываются и не загружаются.
- **OAuth-коннекторы**: коннекторы, требующие OAuth, делегируют авторизацию локальной команде `claude mcp add`, токены сохраняет CLI в месте, которое читает SDK; инструмент не создаёт собственный callback и не хранит client secret.

> Примечание: фраза «не касается API Key» в заявлении о приватности выше относится к состоянию входа самого Claude; ключи коннекторов — это предоставляемые вами добровольно учётные данные сторонних сервисов, они хранятся только локально в зашифрованном виде и никогда не загружаются.

### Отрисовка и уведомления

- Блоки кода Python / JavaScript / Bash можно выполнить локально после подтверждения.
- Уведомления в браузере, а также Feishu, DingTalk, WeCom, Slack, Discord, Telegram и пользовательский Webhook.
- Статистика использования и расходов находится в центре настроек.

### Расширение для браузера

## Быстрый старт

### Предварительные условия

1. Python 3.9+
2. Для нативного рабочего режима требуется Node.js 18+
3. Наличие рабочих учётных данных входа Claude Code; для обычного чата или явного режима CLI также требуется глобальная команда `claude`

```bash
npm install -g @anthropic-ai/claude-code
claude
```

После первого запуска выберите целевую версию и установите её в «Настройки → Общие → Claude Agent SDK». Закреплённая версия приложения использует точный `package-lock.json`, поставляемый вместе с приложением; также можно явно выбрать другую версию из каталога стабильных версий npm для обновления или понижения. claude-web сначала устанавливает во временный каталог, проверяет точную версию и запускает SDK bridge, и только после успеха атомарно переключается на `~/.claude-web/dependencies/claude-sdk/`; при сбое восстанавливается прежняя версия, автоматического обновления не происходит.

`CLAUDE_AGENT_SDK_PATH=/path/to/@anthropic-ai/claude-agent-sdk` может использоваться для переопределения при разработке; внешний каталог без метаданных выбора версии claude-web всё равно должен полностью совпадать с закреплённой версией приложения. Старый каталог установки используется лишь как путь совместимости при миграции; при отсутствии или несовпадении версии рабочий режим явно выдаёт ошибку и не откатывается неявно на CLI. Только явная установка `CLAUDE_WEB_CODE_RUNTIME=cli` заставит новые сессии кода использовать CLI, а сессии, уже закреплённые за SDK, всё равно не переключатся.

### Установка через pip

```bash
pip install --upgrade claude-web-ui
claude-web
```

Адрес по умолчанию: `http://127.0.0.1:8765`

Часто используемые параметры:

```bash
claude-web --open                 # открыть браузер после запуска
claude-web --port 9000            # изменить порт
claude-web --host 192.168.x.x     # привязаться к явному адресу локальной сети
claude-web --extension-path       # вывести каталог расширения для браузера
claude-web --setup-totp           # настроить Authenticator в терминале
claude-web --version              # посмотреть версию
```

### Запуск из исходников

```bash
git clone https://github.com/heng1234/claude-web.git
cd claude-web
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
claude-web --open
```

Затем установите закреплённый SDK со страницы настроек; можно также выполнить `npm ci --prefix claude_web/agent_bridge` в каталоге исходников для установки в каталог разработки.

## Мобильный и удалённый доступ

### Локальная машина и доверенная частная сеть

В «Настройки → Мобильный доступ» посмотрите определённый системой адрес и запустите с явным IP локальной сети:

```bash
claude-web --host 192.168.x.x
```

Затем откройте на телефоне:

```text
http://192.168.x.x:8765
```

Только адреса обратной петли (`127.0.0.1` / `::1`) не требуют входа. Клиенты локальной, частной и публичной сети должны сначала пройти аутентификацию устройства по коду доступа или через Authenticator; после аутентификации доступны те же права инструментов рабочего режима и автоматический режим, что и на компьютере, но управление настройками по-прежнему возможно только с самого компьютера.

### Доступ из публичной сети

- Сначала включите контроль доступа на компьютере в «Настройки → Мобильный доступ».
- Можно использовать одноразовый 6-значный код доступа или включить динамический код Authenticator.
- Обязательно используйте обратный прокси с HTTPS и настройте ограничение скорости входа.
- Не рекомендуется слушать напрямую `0.0.0.0`; предпочтительно привязываться к явному адресу частной сети или использовать частные сети вроде ZeroTier / Tailscale.

Подробные шаги см. в [TOTP_SETUP.md](TOTP_SETUP.md).

## Установка расширения Chrome

1. Запустите Claude Code Web.
2. Откройте «Настройки → Расширение для браузера».
3. Скопируйте каталог расширения либо скачайте ZIP и распакуйте его.
4. Сгенерируйте токен расширения.
5. Откройте `chrome://extensions` и включите режим разработчика.
6. Загрузите распакованное расширение.
7. Укажите в настройках расширения адрес сервиса и токен.

После обновления кода расширения нужно нажать «Перезагрузить» в `chrome://extensions` и обновить используемые веб-страницы. На ограниченных страницах вроде `chrome://` и Chrome Web Store чтение текста невозможно.

## Границы безопасности

- Claude Code Web может читать и изменять локальные файлы, выполнять команды и расходовать квоту Claude, поэтому запускать его следует только на доверенном устройстве.
- Обычный чат не показывает проекты и ветки, но по-прежнему обрабатывается локальным Claude Code; при работе с изменениями кода переключайтесь в рабочую область кода.
- Выполнение блоков кода и автоматический режим рабочей области кода не имеют системной песочницы; аутентифицированные удалённые устройства обладают такими же возможностями выполнения, поэтому не давайте доступ недоверенным устройствам и не выполняйте недоверенный код.
- Контрольная точка Git действует только в репозиториях Git.
- Webhook отклоняет локальные, частные и link-local адреса во избежание SSRF.
- Заголовки пересылки обратного прокси считаются доверенными, только если прямой узел пришёл с адреса обратной петли этой машины; клиент за прокси всё равно должен пройти аутентификацию устройства.
- Authenticator Secret, токены расширения, коды доступа, Webhook Secret, база данных и `history/` не должны попадать в Git.

Перед коммитом можно выполнить:

```bash
python3 scripts/check_sensitive_info.py --paths \
  server.py static/index.html README.md CHANGELOG.md TOTP_SETUP.md
```

## Архитектура

```text
браузер / расширение Chrome
        │  HTTP + SSE
        ▼
FastAPI (Python)
        ├── рабочий режим ── команды NDJSON / события с длинными фреймами ── Node bridge ── постоянный Query Claude Agent SDK
        └── Chat / явный CLI ─────── Claude Code CLI stream-json
        │
        ├── claude-web.db        метаданные сессий, настройки, расходы, авторизованные устройства
        ├── history/*.jsonl      события сессий
        ├── uploads/             загруженные файлы
        └── локальный проект / Git       чтение, изменение, тестирование кода, checkpoint
```

Фронтенд по-прежнему представляет собой одностраничное приложение на нативном JavaScript, основная страница находится в `static/index.html`; pip-пакет использует `claude_web/static/index.html`.

## Известные ограничения

- Неинтерактивный поток SDK или CLI может выдавать события пакетами, поэтому эффект печатной машинки во фронтенде не отражает исходную скорость токенов модели.
- Рабочий режим зависит от Node.js и закреплённой версии Claude Agent SDK; при их отсутствии явно выдаётся ошибка и сессия не переключается на CLI.
- Рабочая область кода по умолчанию использует автоматический режим; всё равно рекомендуется применять её только к доверенным проектам и на доверенных аутентифицированных устройствах.
- Автоматический режим для пользователей не root обходит проверки разрешений CLI; в окружении root / sudo используется совместимое пропускание и не включается принудительно bypass, запрещённый Claude CLI.
- Выполнение блоков кода не изолировано контейнером.
- Расширение для браузера не может читать ограниченные страницы браузера.
